# 0013: Engine defaults are chosen per deployment class

**Status:** Accepted (2026-11-17). Amends ADR0012.

## Context

ADR0012 named LocalAI *the* engine. The migration never ran: LocalAI has not
been started against a real server (handover, Decision A), while Ollama serves
production traffic. Meanwhile the engine landscape sharpened:

- **Ollama** wraps llama.cpp but pins and backports it, so upstream kernel wins
  arrive late, and flags such as `-ncmoe` are not all exposed. Its real product
  is operational ease, and on the easy path (including Apple Silicon) that ease
  is worth more than the speed it leaves behind.
- **llama.cpp server direct** gives the operator every flag, which is what the
  small-card story (ADR0010) actually depends on.
- **LocalAI** remains the only path to real concurrent serving on NVIDIA, via
  its vLLM backend — and concurrency is the unit pilot's defining requirement
  (Decision L fired ADR0010's deferred trigger).
- **Kindi** appeared, targeting old and low-cost cards with expert offload and
  speculative drafting; large measured wins on the floor hardware, but a
  curated model list. Not adopted; benchmark pending (stocktake 2026-11).

Treating "the engine" as one slot is what kept the migration stuck: no single
engine wins everywhere, so no migration could be justified. The classes have
different winners.

## Decision

The engine default is chosen **per deployment class** by `puente init`, and the
operator can always override in `puente.yml`:

| Deployment class | Default |
| --- | --- |
| NVIDIA + concurrency required (institution, unit pilot) | LocalAI with the vLLM backend |
| NVIDIA single small card (8 to 12 GB) | llama.cpp server directly, flags generated by `puente init` (ADR0010 promoted from alternative to default) |
| Easy path, including Apple Silicon | Ollama |
| The floor (old/tiny cards) | undecided; benchmark Kindi vs llama.cpp `-ncmoe` before choosing |

`ENGINE_CAPABILITIES` in `decide.py` is unchanged (`chat`, `coding` only), and
`suggest_backend()` becomes class-aware.

On the Apple class, MLX is a **candidate**, not a default: Ollama on macOS is
llama.cpp with Metal (it does not install MLX underneath), so an `mlx-lm`
server enters the benchmark (stocktake 2026-11) as the alternative for the M5
deployment. The metric is seconds to an acceptable answer — quality-weighted
time — not raw tok/s.

## Consequences

- ADR0012 is amended: LocalAI is **the concurrency engine**, not *the* engine.
  Its catalog half is untouched and stands.
- Ollama is not demoted; it is scoped. It remains the default where the
  operator's time is scarcer than tokens.
- One benchmark before the pilot makes the small-card default factual:
  Ollama vs llama.cpp-direct, same model and quant, on the 4060 Ti.
- The catalog's licence field (Decision F) applies to Kindi if it ever enters:
  AGPL-3.0, surfaced at install time.

## Rejected

- **One engine for everything.** Each class has a different winner; forcing one
  is what produced a stalled migration.
- **Kindi now.** Curated models, v0.6.1, single maintainer, benchmarks
  self-reported. It earns the floor slot only by winning the benchmark on
  hardware we actually ship.
